# Reverse-engineering notes

This project was produced with the workflow described by
[REA — Reverse Engineer Anything](https://github.com/morluto/rea): observe a
running target, extract evidence, reconstruct the behaviour in new source, then
verify the reconstruction against the observations.

The target is the browser build of Galaga at
`https://paoloseverinitest.azurewebsites.net/galaga/galaga.html`.

Nothing was copied from the target. The deliverable is an independent
implementation whose inputs, timing model and rules were derived from the
observations below and from published arcade documentation.

---

## 1. What the target actually is

Fetching the page and reading its source (`reference/site/galaga.html`) gives the
following evidence.

| Observation | Evidence in the page | Consequence for this project |
| --- | --- | --- |
| The game is a **whole arcade machine emulator**, not a JavaScript game. | `galaga = new Module.GalagaMachine()`, and the loop calls `galaga.Run(interval, cb)` where the callback receives a video buffer and an audio buffer. | There is no game logic to copy at the JavaScript level; the rules had to be reconstructed from the game itself. |
| **224 × 288** framebuffer. | `imageData = context.createImageData(224, 288)` | Our logical coordinate system is exactly 224 × 288 (`src/engine/constants.ts`). |
| **2x integer scaling.** | `<canvas width="448" height="576">`, `context.scale(2.0, 2.0)` | The classic renderer draws at 4x internally and is CSS-scaled with `image-rendering: pixelated`. |
| **RGBA byte buffer** written straight into the canvas. | `imageData.data.set(video); context.putImageData(...)` | Confirmed a 1:1 pixel framebuffer; no vector art. |
| **48 kHz mono audio** generated by the emulator. | `audio.freq = 48000`, `Int16Array` ring buffer, `createScriptProcessor`. | We synthesise our own effects with Web Audio at the device rate instead. |
| **Frame interval is clamped to 67 ms** so a slow frame cannot fast-forward the machine. | `if (interval > 67) { interval = 67; }` | Our loop uses a fixed 1/60 s accumulator with a 5-step catch-up cap. |
| **Inputs**: `0` coin, `1` start 1P, `2` start 2P, `←`/`→` move, `Ctrl` fire. | `onKeyDown` / `onKeyUp` switch statements (`keyCode` 48, 49, 50, 37, 39, 17). | Same bindings are supported (`src/app/main.ts`), plus `A`/`D`, `Space`, `Z` as comfort aliases. |
| **Two-player support** exists at the machine level. | `set_Start2Player`, and the page text advertises a two-player game. | Implemented as alternating turns with independent scores. |
| Boot takes a moment before input is accepted. | `setStatus` triggers `start()` only when the runtime reports ready. | We model this as `phase: 'attract'` with a title screen. |

## 3. How the reconstruction is organised

`src/engine/` is a renderer-free simulation:

| Behaviour | Where |
| --- | --- |

## 4. Deliberate deviations

* **Art is original.** Sprites are drawn from pixel primitives
  (`src/render/classic/sprites.ts`); no ROM tiles are extracted or reproduced.
  Shapes are recognisably in the same family, not identical.
* **Fleet size.** The formation musters 36 ships in five ranks (4 flagships,
  16 butterflies, 16 bees) with 40 ships used for challenging stages. This is the
  layout the reference visibly presents; the count is documented here rather
  than claimed as a bitmap-exact reproduction.
* **No coin gate.** Pressing `1`/`2` starts immediately; `0` still increments the
  credit counter for authenticity.
* **No ROM emulation.** We do not run the arcade program. The rules above are
  reimplemented in TypeScript, which is what makes the identical-engine
  requirement achievable in the first place.
* **Audio.** Effects are synthesised per event rather than streamed from the
  emulated sound hardware.
* **Challenging-stage group bonus thresholds** (1000 / 1500 / 2000 / 3000 by
  stage band) follow the published table; the exact per-group grouping is our
  interpretation, implemented as flights of eight.

## 5. The no-fire bug

Galaga's most famous fault is not a hidden cheat code; it is a slot leak, and it
is documented down to the instruction level by Christopher Cantrell's
disassembly work at [Computer Archeology](http://www.computerarcheology.com/Arcade/Galaga/).

The chain of evidence:

| Observation | Source |
| --- | --- |
| Enemy fire lives in **eight shared slots**; `InitiateBeeShot` scans the table for a free entry and gives up when none is free. | disassembly of CPU2 at `0D54`–`0DF4` |
| A shot is initialised with its parent ship's coordinates, so a ship at X=0 creates a shot at X=0. | `0D88` onward |
| `MoveBeeFire` skips any bullet whose **X is 0**, because the hardware uses X=0 to mean "sprite disabled". | CPU1 `1ECC`: `AND A / JR Z` |
| `RemoveBeeShot` frees a slot only when the bullet's **Y** leaves the screen — it never checks X. | CPU1 `2560`–`2588` |
| Therefore a shot at X=0 is never moved and never freed: the slot is gone for the rest of the credit. | Cantrell's hypothesis, confirmed with a slot-status instrument |
| The wide end-game sweep that drags edge ships off-screen only starts with fewer than seven ships left. | Movement subcommand 9, and the update note on the page |
| Players describe the result as "kill everything but the two edge bees and dodge for 15 minutes". | [GameFAQs](https://gamefaqs.gamespot.com/arcade/583972-galaga/cheats), [Jason Eckert](https://jasoneckert.github.io/myblog/the-galaga-no-fire-cheat-mystery/), [Set Side B](https://setsideb.com/the-no-fire-trick-in-galaga/) |

### How this project models it

`GalagaEngine.shotSlots` is an eight-entry table with three states: `free`,
`live` and `hung`.

* `enemyShoot` allocates a free slot and refuses to fire when there is none, so
  eight is a hard cap on enemy bullets in flight (`tests`: "enemy fire is
  limited to the eight shared shot slots").
* If the firing ship is within `SHOT_JAM_EDGE` pixels of a screen edge there is a
  `SHOT_JAM_CHANCE` chance the shot is dropped at X=0 instead: the slot becomes
  `hung` and no bullet is created (`shotJam` event).
* `syncShotSlots` frees `live` slots when their bullet leaves play; it never
  frees `hung` ones.
* `noFireActive` is true when all eight are hung, and `enemyShoot` returns
  immediately in that state.
* Divers get the wider sweep when fewer than seven ships remain, matching the
  documented trigger for edge ships reaching X=0.
* `setNoFireBug(true)` — what the `B` key and the **No-fire bug** button call —
  corrupts all eight slots at once, which is the state a real cabinet reaches
  after fifteen minutes. The table resets on a new credit, as on the machine.

## 6. The expert pilot

### Prior art, and why it was not used

The existing Galaga agents are reinforcement learners trained on emulated
consoles, not on this game:

* [GaRLaga](https://github.com/RobertMonaco/GaRLaga) — DQN/RL against an
  emulated NES Galaga.
* [Galaga_AI](https://github.com/georgefidler1709/Galaga_AI) — RL against
  NES/Atari 2600 Galaga.

Both need a ROM and an emulator, and neither transfers to a reimplementation
with its own state representation. Training an agent here was out of scope, so
the pilot is a heuristic player written from published expert technique.

### Techniques encoded

From [Jordan Dorrington's strategy tips](https://setsideb.com/jordan-dorringtons-galaga-strategy-tips/)
and the [StrategyWiki walkthrough](https://strategywiki.org/wiki/Galaga/Walkthrough):

| Advice | Implementation |
| --- | --- |
| Fire constantly while lined up; entering ships cannot shoot back. | `shouldFire` only triggers when a ship is in the lane; entry ships are ignored as targets unless the stage is challenging. |
| Keep moving — aimed shots hit where you were. | Under threat the pilot never stops: it sweeps and reverses at `think`. |
| Dive bombers are the danger and pay double. | `pickTarget` scores `dive`/`beam` +3.2, `return` +1.2. |
| Rescue the captured fighter. | `capturedShip` adds +5.5, the largest single weight. |
| Stay out of the tractor beam. | The beam is added as a high-weight hazard in `collectHazards`. |
| Clean up stragglers by hugging an edge and drifting across. | The sweep naturally does this; wall proximity only reverses direction. |
| A lone flagship never captures. | `updateScheduling` requires more than one living boss. |

### How it decides

The pilot has one advantage a person does not: it can read the dive splines the
simulation is already following. Every decision (about 20 times a second):

1. **Bullets** — projected analytically to where they cross the fighter's row.
2. **Divers** — the ship's own `BeamPath` is sampled forward, so the exact band of
   lanes it will sweep while crossing the fighter's row is known, not guessed.
3. **Tractor beam** — treated as a permanent no-go band.
4. **Planning** — a 26-step (1.3 s) dynamic programme over 6-pixel lanes finds the
   cheapest path: danger is additive along the path, each lane change costs a
   little, and a weak alignment term keeps the ship near a target. The pilot
   executes only the first step, then replans.
5. **Firing** — independent: shoot whenever a ship is in the lane, always during
   a challenging stage.

The earlier version of this pilot was reactive (sweep and reverse when the lane
ahead turned bad). It averaged one death every ~8 stages and could not finish.
The planner below it is what changed: with exact dive prediction it survives a
full three-hour run.

### Measured

`tools/train.mjs` runs the simulation with no rendering and no audio at roughly
**8,700× real time** — a three-hour game evaluates in about 1.4 seconds, which is
what made tuning practical.

* Seeds 1 and 7: **stage 255 reached and cleared**, ~750 000 points at the
  ending, 13 deaths across the full run (extra fighters earned from score keep
  the run alive), no game over.
* Continuing past the ending, the same seeds reach ~1.77 million points after
  200 minutes.

At 256× in the browser the same run takes about a minute.

## 7. The ending

The arcade machine runs to stage 255 and then behaves strangely — some revisions
show a kill screen, others wrap to a "stage 0" with fast fire
([Dorrington's tips](https://setsideb.com/jordan-dorringtons-galaga-strategy-tips/)
covers this). This project turns that boundary into a proper ending: clearing
stage 255 raises a `victory` phase with `MISSION COMPLETE`, a final score, a
camera pull-back, fireworks and a fanfare, then returns to attract mode. The demo
plays another game after it.

## 8. Verification

The reconstruction is checked in four ways:

1. **Behavioural tests** — `tests/engine.test.ts` covers stage composition,
   challenging-stage detection, scoring values, fleet arrival, stage
   advancement, extra lives, tractor-beam capture, rescue/twin fighter,
   invulnerability, attract mode, the eight-slot fire limit, forcing and
   releasing the no-fire bug, slot accumulation, the pilot's score, determinism
   and movement, and the stage-255 victory (including the return to attract).
2. **Determinism** — two engines with the same seed and the same scripted inputs
   are advanced for 45 seconds; their full-state hashes must match at every
   sampled frame. The same check is run over a 30-second autopilot game. This is
   the property that makes the side-by-side mode honest.
3. **Long-run training** — `tools/train.mjs` and `tools/balance.mjs` run the
   simulation headless (no rendering, no audio) at thousands of times real time
   to check that the game is survivable and that the pilot completes all 255
   stages.
4. **Visual comparison** — `tools/shoot-final.mjs`, `tools/shoot-features.mjs`
   and `tools/shoot-victory.mjs` drive a headless browser through every mode,
   the challenging stage, the tractor beam, the expert demo, the no-fire bug, a
   256× run and the ending, capturing screenshots in `shots/`. The side-by-side
   captures show both renderers agreeing on every ship position.
